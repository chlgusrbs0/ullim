# YAMNet classifier implementation plan

> For agentic workers: use superpowers:executing-plans task by task.

**Goal:** Bundle an offline YAMNet classifier behind the existing SoundClassifier contract (#19).
**Architecture:** A pure Kotlin adapter validates PCM windows, score arrays and ownership. An Android LiteRT interpreter owns fixed input/output buffers and closes deterministically. Loading/inference stays off the DSP thread when integrated in #22.
**Tech stack:** Existing Kotlin/Wear app; official LiteRT Interpreter 1.4.2 CPU runtime.
**Spec:** GitHub issue #19; docs/architecture.md; user instruction to continue implementation/local verification without a watch, keeping Draft PRs.

## Global constraints
- 16,000Hz mono PCM16; 15,600 float32 input values and 521 scores.
- Preserve core/Contracts.kt interfaces; no PCM files/logs/network permission.
- No GitHub Actions; no device success claims; main target with Closes #19; Draft until device inference and predecessors verified.

## Review focus
- Invalid model/labels fail closed and release the interpreter.
- Wrong window lengths cannot invoke inference.
- NaN or malformed scores cannot become classifications.
- Close is idempotent; inference after close fails explicitly.
- Timestamps remain in the capture monotonic domain and expire after the window, not before its end.
