# YAMNet 분류기 구현 계획

> 과거 작업 계획입니다. 당시의 요구사항·체크 상태를 보존하며, 최종 구현 및 검증 상태는 현재 기술 문서를 기준으로 합니다.

> 작업자 지침: superpowers:executing-plans 단계별 적용.

**목표:** 기존 SoundClassifier 계약 뒤에 오프라인 YAMNet 분류기 번들 (#19).
**구조:** 순수 Kotlin 어댑터가 PCM 창, 점수 배열 및 소유권을 검증한다. Android LiteRT 인터프리터가 고정 입출력 버퍼를 소유하고 결정적으로 닫는다. #22 통합 시 로딩·추론은 DSP 스레드 외부.
**기술:** 기존 Kotlin/Wear 앱, 공식 LiteRT Interpreter 1.4.2 CPU.
**명세:** #19, docs/architecture.md, 워치 없이 로컬 검증 후 Draft PR 유지하라는 사용자 지시.

## 공통 제약
- 16,000Hz mono PCM16, float32 15,600개 입력 및 점수 521개.
- core/Contracts.kt 인터페이스 유지, PCM 파일·로그·네트워크 권한 없음.
- Actions·기기 성공 주장 금지. main 대상 Closes #19, 기기 추론·선행 검증 전 Draft.

## 검토 중점
- 잘못된 모델·레이블은 안전하게 실패하고 인터프리터 해제.
- 잘못된 창 길이로 추론 호출 금지.
- NaN·잘못된 점수를 분류 결과로 만들지 않음.
- 닫기 멱등, 닫은 뒤 추론 명시 실패.
- 감지 단조 시간 도메인 유지, 창 종료 후 만료.
