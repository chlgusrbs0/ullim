# 울림 해커톤 핵심 MVP 변경 계획

> 과거 작업 계획입니다. 당시의 요구사항·체크 상태를 보존하며, 최종 구현 및 검증 상태는 현재 기술 문서를 기준으로 합니다.


2026-11-14 사용자 요청에 따른 간단한 실행 범위다. 코드별 반복 검증·다단계 리뷰·추가 승인·상용 문서 작업은 제외한다. 이 문서는 구현 완료 기록이 아니다.

## 목표와 확정 범위

- 화면을 계속 보지 않고 소리의 강약·지속·리듬을 촉각으로 구별한다.
- 현재 펄스 질감은 허용한다. 매끈함 개선, 새 모터 API 탐색, 펌웨어 변경은 이번 범위에서 제외한다.
- AI는 필수 제품 기능이다. 첫 진동은 AI 판단을 기다리지 않으며, AI 실패 시 기본 소리 전달은 계속한다.
- 기존 Watch7 단독 Kotlin 앱과 번들 YAMNet을 활용한다. 새 모델 학습·대형 생성 모델·서버·휴대전화 의존을 추가하지 않는다.

## 구현 순서

2026-11-14 추가 사용자 승인: 작은/중간 소리는 이전 짧은 펄스, 높은 요청은 긴 펄스로 표현한다. 후속 착용 피드백에 따라 요청60~75%에서 ON 시간을 점진 이동하며 총ON/60ms/실제 무음은 유지한다. 중간값 과증폭과 AI 종류별 DETAIL/CONTRAST 곡선은 제거하고, AI는 동일 문맥에서 미세한 시간적 흔들림을 완화한다. 이 추가 승인이 아래 초기 곡선 계획보다 우선한다. 실제 체감 효과는 설치 후 확인한다.

### 1. 지속음과 자기 진동 재입력 처리

- 대상: `NoiseGate.kt`, `LiveDsp.kt`, `MotorOutputTimeline.kt`, `MotorNoiseSuppressor.kt`, `ListeningService.kt`.
- 활성 소리가 배경 기준값으로 계속 흡수되지 않게 상승 방향 학습 조건을 분리한다. 시작/종료 판단에 서로 다른 문턱을 사용해 경계에서 불필요하게 깜박이지 않게 한다.
- 모터 작동·잔향으로 오염된 구간은 배경 기준 학습에서 제외한다. 기존 성공 보정과 현재 출력 주기는 보존한다.
- 소리 종료 뒤 자기 진동으로 감지가 연장되는지, 긴 소리가 중간에 사라지는지를 핵심 확인 대상으로 둔다.
- 장시간 일정한 소리는 자동으로 불필요한 소음으로 분류해 삭제하지 않는다. 모든 외부음과 모터음의 완전한 분리를 약속하지 않는다.

### 2. 실제 출력 범위를 고려한 강약 변환과 AI 연결

- 대상: `EnvelopeHapticMapper.kt`, `HybridHapticMapper.kt`, `PulseFallback.kt`, 필요 시 `HapticScheduler.kt`.
- 최종 펄스 변환 뒤에도 작은/큰 입력의 차이가 남도록 단조로운 강약 곡선을 조정한다. 출력 범위는 현재 기기의 한도를 따른다.
- AI의 소리 문맥과 실시간 강약·시작 특성을 함께 사용한다. 기본 변환과 강약 대비를 강조하는 변환부터 좁게 구현하고, 의미 없는 작은 배율 변경으로 끝내지 않는다.
- 원래 소리의 발생 횟수·길이·반복 간격을 유지한다. 늦게 도착한 AI 결과로 이미 끝난 소리를 다시 울리거나 별도 종류별 알림 패턴을 만들지 않는다.
- 짧은 소리 도중 뒤늦게 변환 방식이 바뀌어 가짜 강약 변화가 생기지 않도록 적용 시점을 제한한다. 불확실하거나 오래된 AI 결과에는 기본 변환을 사용한다.
- 모터 간섭 상태를 AI 결과 적용에도 공유한다. 모든 모터 구간을 무조건 차단해 AI가 계속 적용되지 못하는 방식은 피한다.
- 이 변화가 실제로 더 잘 구별되는지는 손목에서 확인한다. 단순 명령값 차이를 지각 개선으로 기록하지 않는다.

### 3. AI가 포함된 기본 사용 흐름과 한 APK 통합

- 대상: `SettingsRepository.kt`, `SettingsRuntime.kt`, `AiRuntime.kt`, `ListeningService.kt`, 필요한 안내 문자열.
- 신규 기본 사용은 AI 켜짐으로 연결한다. 이미 저장된 사용자의 OFF 선택은 존중하며, OFF는 비교와 문제 확인에 사용할 수 있게 둔다.
- AI 분석은 비동기로 유지하고 시작/중지·화면 꺼짐 중 소리 처리를 막지 않게 한다.
- 그래프·분류명 화면 확장, 자동 개인화, 새로운 상태 알림 체계는 이번 핵심 변경에 추가하지 않는다.

## 최소 확인과 통합

- 변경을 묶은 뒤 `:app:testDebugUnitTest :app:assembleDebug :app:lintDebug`를 한 번 실행한다. 새 테스트는 실제 수정한 결함과 핵심 동작을 확인하는 소수만 추가하며, 형식적인 RED/GREEN 반복은 요구하지 않는다.
- 새 실패가 나오면 해당 원인만 수정·재확인한다. 통과한 동일 결과를 여러 검토자가 반복 확인하는 단계를 두지 않는다.
- 같은 APK에서 조용함 → 작은/큰 소리 → 짧은/긴 소리 → 반복 소리 → 소리 종료 → 사용자 중지를 짧게 확인한다. 화면을 끈 사용과 AI ON/OFF 차이도 가능한 범위에서 함께 확인한다.
- 워치 연결이 안 되면 개발·PR·가능한 머지는 계속하고 착용 미확인을 남긴다. 모델 단독 실행, 앱의 명령, 실제 손목 체감을 구분해 결과를 보고한다.
- #9(지속음 회귀), #17(모터 간섭), #21(AI 정책), #28(기본 설정), #36(통합), #38(APK)와 연결한다. 기존 완료 이슈에서 회귀를 수정하면 재오픈 또는 버그 이슈로 추적한다.
- 기존 #37/#39의 정식 구별률·물리 지연 평가를 이번 구현·머지의 선행 작업으로 확대하지 않는다. 미수행 평가를 통과했다고 하거나 기존 이슈를 일괄 종료하지 않는다.

## 이번에 하지 않는 작업

개인정보 보호 방침 확장, 상용 출시 준비, 광범위한 리팩터링, 화면 꾸미기, 추가 선행사례 조사, 매끈함 자체의 최적화, 학습 데이터 수집 및 새 모델 훈련.
