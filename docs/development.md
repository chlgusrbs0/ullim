# 개발 및 설치 안내

[문서 안내](README.md)

울림을 로컬에서 빌드하고 갤럭시 워치7에 설치하는 절차다. 아래 검증 명령과 체크리스트는 재현용이며 새 실행 결과가 아니다.

## 1. 유지보수 원칙

- **GitHub Actions 금지.** 워크플로 파일을 만들거나 실행·재실행하지 않는다.
- 향후 변경은 별도 이슈·브랜치·PR에서 검토한다. 완료된 작업만 병합 후 완료로 종료하고, 진행하지 않기로 한 작업은 검증 상태를 그대로 남긴다.
- 협업 작업 시 AGENTS.md의 선점·검토 규칙을 따른다.
- 문제가 발견되면 해당 원인 이슈를 다시 열거나 버그 이슈를 만든다. 미검증 테스트를 통과로 기록하지 않는다.

## 2. 개발 환경

- JDK 17, Android SDK Platform 36, Build Tools 35.0.0, Platform Tools
- Gradle Wrapper 8.13, Android Gradle Plugin 8.13.2, Kotlin/Compose compiler 2.1.21, Wear Compose Material 3 Expressive 1.5.0
- `ANDROID_HOME` 또는 커밋하지 않는 `local.properties`의 `sdk.dir`로 SDK 경로 설정
- 갤럭시 워치7, 실제 기기 연결 및 개발자 옵션·무선 디버깅/adb
- Kotlin / Wear OS 단일 `app` 모듈: `com.ullim.watch`, minSdk 34 / compileSdk 36 / targetSdk 35
- 서버·스마트폰·노트북용 실행 모듈은 구성하지 않는다

## 3. 로컬 명령

```bash
./gradlew :app:testDebugUnitTest
./gradlew :app:assembleDebug
./gradlew :app:lintDebug
```

Windows PowerShell에서는 `./gradlew.bat`를 사용한다. 위 명령의 **실제 실행 결과와 실패 개수**를 PR에 남긴다. `testDebugUnitTest`가 `NO-SOURCE`로 끝나면 테스트를 수행한 것으로 기록하지 않는다.

처음 실행할 때 Wrapper와 Maven 의존성을 내려받기 위한 개발 PC의 인터넷 연결이 필요하다. 앱의 런타임 네트워크 의존성과는 별개다. Wrapper의 배포 ZIP은 고정된 SHA-256으로 검증한다.

워치의 개발자 옵션에서 무선 디버깅을 켜고, 같은 네트워크의 PC에서 워치에 표시된 주소·포트로 연결한다. 페어링 포트와 연결 포트는 다를 수 있으며 연결 정보를 저장소에 기록하지 않는다.

```bash
adb pair WATCH_IP:PAIRING_PORT
adb connect WATCH_IP:DEBUG_PORT
adb devices -l
```

연결된 여러 기기를 혼동하지 않도록 워치의 serial을 명시한다.

```bash
adb -s WATCH_SERIAL install -r app/build/outputs/apk/debug/app-debug.apk
adb -s WATCH_SERIAL shell am start -W -n com.ullim.watch/.MainActivity
```

워치의 모델·OS/API 버전, 설치 성공·실행 시각과 원형 화면 스크린샷을 검증 증거로 남긴다. 최종 MVP에는 시작/중지·마이크·DSP/진동·알림 경로가 연결되어 있다. 시작은 보이는 앱 화면의 사용자 동작과 마이크 권한으로만 허용하며 서비스는 START_NOT_STICKY이고 부팅/시스템 종료 후 재시작하지 않는다. 중지 후 마이크 정리가 끝나기 전에는 새 소유자를 연결하지 않는다. 알림 권한 거부 시 표시 제한을 안내한다. 새 검증에서 워치가 연결되지 않았다면 설치·실행/화면 꺼짐은 미실시로 기록한다. 기초 설치의 기존 기록과 최신 통합본의 미완료 평가를 구분한다.

## 4. 시험 유형별 검증 근거

DSP 픽스처/부하 시험은 `./gradlew :app:testDebugUnitTest --tests '*DspBoundaryTest' --rerun-tasks`로 재현한다. 테스트는 무음·낮은 음량·클리핑·지속톤·대역 제한 잡음·노크·발화 유사 변조를 코드로 생성하며 실제 음성을 보관하지 않는다. 10분 분량 30,000프레임의 처리 시간, DSP P95/최대 시간, JVM heap 전후를 JUnit XML의 `system-out`에 출력한다. 빠르게 주입하는 데스크톱 합성 시험이며 워치7의 10분 실시간 녹음이나 물리 지연 시험이 아니다. heap 전후 차이는 GC 시점의 영향이 있으므로 메모리 누수 부재/retained memory 증거로 해석하지 않는다.

| 영역 | 최소 증거 | 판정 유의사항 |
|---|---|---|
| 문서 | 문서 링크·범위 체크리스트·선점/PR 규칙 검수 | Gradle/실기기 테스트는 '해당 없음/미실시' |
| 앱 기초 | 빌드 로그, 기본 UI 실기기 실행, 공통 계약 테스트 | 빌드 가능성과 실제 진동/AI 기능 완성을 혼동 금지 |
| 오디오·런타임 | 워치7 마이크·화면 꺼짐·권한 회수·시작/중지 로그 | 에뮬레이터로만 통과 처리 금지 |
| DSP | 합성 오디오 픽스처·강도/리듬 테스트·성능 수치 | 입력 원음 보관·유출 금지 |
| 촉각 | 워치7 기능 탐지·강약·반복·중단 시험·물리 지연 | 앱이 진동 명령을 보낸 것과 실제 물리 진동을 구별 |
| AI | 모델 출처/해시, 워치7 추론 로그, AI OFF/Fallback 비교 | 모델 성능을 다른 기기 수치로 대체 금지 |
| UI | 원형 화면 스크린샷, 접근성·권한·오류 화면 검사 | 실측하지 않은 진동을 실측 그래프라고 표시 금지 |
| 전체 | 회귀 테스트·실기기 로그·블라인드 구별 평가·APK 해시 | 실패/미측정/중단 버그가 있으면 완료 불가 |

## 5. PR 본문 권장 형식

```markdown
## 연결 이슈
Closes #N

## 구현 내용
- [변경된 기능과 파일]

## 완료 조건 증거
- [ ] 해당 이슈의 DoD 항목 1 — 근거 링크/로그
- [ ] 해당 이슈의 DoD 항목 2 — 근거 링크/로그

## 검증
- 명령: [실행한 명령]
- 결과: [성공/실패, 실패 개수]
- 워치7 실기기: [실시/미실시/해당 없음, 기기/OS와 결과]

## 미해결 사항
- [미해결 제한/버그/후속 이슈]
```

위의 `Closes #N`은 반드시 실제 이슈 번호로 변경하여 PR **본문**에 적는다. PR이 `main`에 병합될 때 GitHub가 이슈를 자동 종료해야 한다. 완료로 닫는 경우에 적용한다. 사용자 지시에 따른 진행 계획 없음(Not planned) 종료와 검증 완료는 구분한다.

## 7. 보존된 정식 평가 기준

아래는 해커톤 개발 당시의 정식 인수 기준이다. 추가 평가를 진행하지 않기로 종료했으므로 이를 통과했다고 기록하지 않는다.

- 워치7 출력 장치 능력과 입력→촉각 경로 지연은 실제 기기에서 확인해야 한다.
- #37에서 사용자 블라인드 시험을 수행하며, 강도 3단계와 리듬 3종의 정답률을 **각각 80% 이상**으로 확인한다.
- 물리적 소리 발생→물리적 진동 반응은 **P95 500ms 이내**를 목표로 하고, 실제 물리 반응 측정 실패나 미측정이면 합격 처리하지 않는다.
- #38에 최종 설치 가능한 APK, 빌드 재현, 시연 증거를 확보한다.
- 정식 v1.0 인수는 모든 필수 기준의 충족과 알려진 차단 결함 0건 확인을 요구했다. 이 기준은 미완료 상태다.
- 향후 평가를 재개해 목표 미달이면 원인을 해결하고 재시험한다. 기준 변경에는 사용자 명시적 승인이 필요하다.

## 8. 개인정보·라이선스

- 원본 PCM·주변 대화 녹음은 파일·로그·네트워크로 내보내지 않는다.
- 외부 오픈소스의 코드 복사와 알고리즘 참고를 구분하고 직접 사용한 라이선스 고지는 보존한다.
- 비밀키, 서명키, 개인 계정 토큰을 소스 저장소에 올리지 않는다.

## 9. 워치7 진동 기능 조사

[실기기 기능 표와 실패·미측정 기록](evidence/issue4-watch7.md)을 참고한다. 현재 SM-L300 / Android 17 베타 ZZK1은 강도 API 지원을 보고하지만 같은 길이의 강도 차이는 사용자에게 구별되지 않았고, 엔벌로프는 미지원이다. 단일 긴 진동과 짧은 명령 교체의 연속감도 다르다. 이 조사는 출력 품질 합격을 뜻하지 않으며 #18·#37·#39의 강약·연속성·물리 지연 검증은 별도로 충족해야 한다.
