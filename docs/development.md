# 울림 로컬 개발·검증 안내

**이 문서는 협업용 절차 명세**다. 아직 #2 앱 초기화 전이므로 Android Gradle 명령이나 갤럭시 워치7 테스트를 실제 실행·통과했다고 주장하지 않는다.

## 1. 기본 원칙

- **GitHub Actions 금지.** 워크플로 파일을 만들거나 실행·재실행하지 않는다.
- 코드·기능은 GitHub Issue 선점 → 브랜치 → 로컬 테스트 → PR → `main` 병합 → 자동 이슈 종료 순서로 작업한다.
- 작업을 시작하기 전 **전체 이슈 댓글과 열린 PR**을 확인하고, 선점 댓글을 게시한 직후 **다시 조회**해 최초 유효 선점인지 확인한다.
- 문제가 발견되면 해당 원인 이슈를 다시 열거나 버그 이슈를 만든다. 미검증 테스트를 통과로 기록하지 않는다.

## 2. 개발 환경

- Android Studio 및 해당 프로젝트와 호환되는 Android SDK/JDK/Gradle
- 갤럭시 워치7, 실제 기기 연결 및 개발자 옵션·무선 디버깅/adb
- Kotlin / Wear OS 단일 `app` 모듈 (#2에서 최초 생성)
- 서버·스마트폰·노트북용 실행 모듈은 구성하지 않는다

## 3. 로컬 명령 (앱 초기화 #2 완료 후에만)

```bash
./gradlew :app:testDebugUnitTest
./gradlew :app:assembleDebug
```

Windows PowerShell 등에서 Gradle Wrapper 실행 파일 명령은 환경에 맞게 사용한다(예: `gradlew.bat`). 위 명령의 **실제 실행 결과와 실패 개수**를 PR에 남긴다. 문서 변경만 있는 #1에서는 이 명령을 실행했다고 주장하지 않는다.

실기기 설치는 #2에서 adb 연결을 확립한 뒤 다음 형식으로 확인한다.

```bash
adb devices
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

워치의 페어링 상태, 실제 ADB 연결 ID, 설치 성공·실행 시각을 기록한다. 아직 생성되지 않은 APK 경로를 성공 증거로 삼지 않는다.

## 5. PR 본문 권장 형식

```markdown
## 연결 이슈
Closes #N

## 구현 내용
- [변경된 기능과 파일]

## 완료 조건 증거
- [ ] 해당 이슈의 DoD 항목 1 — 근거 링크/로그
- [ ] 해당 이슈의 DoD 항목 2 — 근거 링크/로그

## 검증
- 명령: [실행한 명령]
- 결과: [성공/실패, 실패 개수]
- 워치7 실기기: [실시/미실시/해당 없음, 기기/OS와 결과]

## 미해결 사항
- [미해결 제한/버그/후속 이슈]
```

위의 `Closes #N`은 반드시 실제 이슈 번호로 변경하여 PR **본문**에 적는다. PR이 `main`에 병합될 때 GitHub가 이슈를 자동 종료해야 한다. 병합 전 수동 종료 금지.

## 6. 워치7 실기기 체크리스트

- [ ] 워치와 실제 연결 확인, 앱 설치·실행 확인
- [ ] 마이크 권한을 명시적으로 허용한 뒤 감지 시작
- [ ] 무음/약한 소리/큰 소리/연속 소리/노크 리듬 시나리오
- [ ] 화면 꺼짐·워치 잠금·홈 전환 후 촉각 반응 유지
- [ ] AI ON/OFF에 관계없이 기본 DSP 작동
- [ ] 사용자 중지/권한 취소 시 마이크·진동·알림·서비스 정리
- [ ] 앱 재시작 뒤 상태 정확성·설정 유지 확인
- [ ] 지원되지 않는 진동 제어와 API 폴백의 정직한 표시
- [ ] 개인정보 비저장·오프라인 동작 확인

## 7. 성능 검증과 릴리스 게이트

- #18에서 워치7 출력 장치 능력과 입력→촉각 경로 지연을 검증하고 불가할 때는 해결 전까지 이슈를 닫지 않는다.
- #37에서 사용자 블라인드 시험을 수행하며, 강도 3단계와 리듬 3종의 정답률을 **각각 80% 이상**으로 확인한다.
- 물리적 소리 발생→물리적 진동 반응은 **P95 500ms 이내**를 목표로 하고, 실제 물리 반응 측정 실패나 미측정이면 합격 처리하지 않는다.
- #38에 최종 설치 가능한 APK, 빌드 재현, 시연 증거를 확보한다.
- #39는 #1~#38의 병합·완료와 알려진 차단 버그 0건을 확인한 뒤에만 종료한다.
- 실측으로 목표가 달성되지 않으면 결과만 고지하고 종료하는 것이 아니라 원인을 해결하고 재시험한다. 합격 기준 변경에는 사용자 명시적 승인이 필요하다.

## 8. 개인정보·라이선스

- 외부 오픈소스의 코드 복사와 알고리즘 참고를 구분하고 직접 사용한 라이선스 고지는 보존한다.
- 비밀키, 서명키, 개인 계정 토큰을 소스 저장소에 올리지 않는다.
