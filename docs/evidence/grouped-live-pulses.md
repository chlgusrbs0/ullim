# 실시간 펄스의 ON 시간 묶기 — 2026-11-14

사용자는 PR79에서 실제 경보와 대화의 추적 및 작아지는 소리의 촉각 변화를 확인했지만 진동이 약하다고 보고했다. 추가 비교에서 `H · 최댓값255 · 600ms`가 실시간 감지보다 확실히 강하다고 답했다. 이는 단일 긴 효과와 실시간 출력 사이의 차이를 보여주며, 모터 자체 한계를 확정하거나 어떤 한 가지 원인만 입증하지는 않는다.

조회한 약49초 수치 로그에는 최대 요청0.9998106이 있으며, 2450프레임 중 AI 조정38프레임을 확인했다. 같은 세션 누적 AI 추론389회/오류0회다. 알람의 정확한 분류명이나 실제 모터 가속도를 기록한 로그는 아니다. 원음은 저장하지 않았다.

## 변경

- 기존60ms 배치와 첫 명령 일정은 유지한다. 추가 대기나 출력 꼬리를 만들지 않는다.
- Watch7의 pulse fallback에서 연속20ms 프레임의 ON 시간이 서로2ms 이내이면 최대3프레임을 한 펄스로 합친다. 예: 요청50%의 `10ms ON/10ms OFF ×3`을 `30ms ON/30ms OFF`로 출력한다. 전체60ms와 ON 합계30ms는 같다.
- 실제 무음 프레임과 뚜렷한 강약 변화는 별도 구간으로 남긴다. 약/중/최대 요청의 배치 ON 시간은 각각12/30/60ms로 구분된다. ON 시간의 분포를 바꾸므로 유음 내부 최대40ms의 세부 위치는 달라질 수 있다.
- 표준 amplitude 및 AI/DSP 매핑은 바꾸지 않는다. 최대 출력의 연속60ms 요청을 OS에서 반복 갱신하는 특성도 남는다. 따라서 이번 변경으로 H600ms와 같은 물리 세기를 보장하지 않는다.
- 보정도 같은 인코더를 사용하며 키에 `pulse=grouped60-v1`을 추가한다. 이전 숫자 프로필은 지우지 않고 새3초 보정을 요구한다. 기존 보정을 새 파형의 검증으로 재사용하지 않는다.

[Android Waveform API](https://developer.android.com/reference/android/os/VibrationEffect#createWaveform(long[],%20int[],%20int))에서 시간0인 항목은 무시되며 amplitude0은 OFF, DEFAULT_AMPLITUDE는 기본 세기다. 100% 요청이 실제 물리 세기100%를 뜻하지 않는다.
