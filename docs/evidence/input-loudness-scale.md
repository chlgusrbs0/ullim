# 입력 크기에서 진동 요청으로의 보수적인 환산 조정 — 2026-11-14

사용자가 명확히 한 문제는 소리 수집 자체보다 큰 소리에도 앱의 진동 요청이 작다는 점이다. 사용자 추가 수집은 중지했고 임시 nativeprobe도 제거했다. 이번 변경은 사용자 녹음이나 통화 처리를 바꾸지 않고 합성PCM로 확인한다.

## 원인과 변경

기존 소리 수준은 배경을 뺀 RMS 엔벌로프에 대해 `x=sqrt(signal*sensitivity*2)`였다. 기본 민감도와 배경0.005, 지속 입력이라는 가정에서 RMS0.08은 약0.386,0.15도 약0.538이다. 이 수치는 실제 음압 비율이 아니므로, 소리는 충분히 들려도 낮은 진동 영역만 쓰는 계산이 될 수 있다.

NoiseGate의 공통 수준 정규화에 `x/(x+0.3*(1-x))`를 적용한다. 같은 가정의0.08은 약0.677,0.15는 약0.795로 높아진다.0과1을 보존하고 범위 안에서 단조 증가하며, 낮은 단계부터 조기에 전부1로 자르는 선형 증폭 대신 위쪽 차이도 남긴다.0.3은 해커톤 개발용 기본값이며 물리 음압이나 체감으로 확정한 보정값이 아니다.

- 감지 문턱, 배경 학습, 원본 PCM/RMS/envelope/onset 및20/60ms 일정은 유지한다. 자동 음량 조절이 아니며 소리 종류별로 크기를 정하지 않는다.
- AI는 기존의 동일 문맥 미세 안정화를 유지한다. 모터 보정·요청에 따른 파형과 보정의0.2/1.0 출력도 같으므로 새 모터 보정은 필요 없다.
- 이전 곡선은 knee1, 새 기본은 knee0.3으로 같은 실제 DSP→Mapper→WaveformRenderer에 합성 신호를 통과시켜 비교한다. 사용자 음성 샘플은 쓰지 않는다.
