# 소리 크기에 따른 짧은/긴 펄스 전환 — 2026-11-14

PR80 보정은 저장됐으나 사용자 착용 보고에서 작은 소리까지 모두 강하게 느껴졌다. 사용자는 낮은/중간 요청에는 PR79의 짧은 펄스, 높은 요청에는 긴 펄스를 쓰도록 승인했다. 소리 종류로 중요도를 정하거나 대화는 약하게·경적은 강하게 고정하지 않는다.

## 구현

- 공통 매핑에서 중간 소리 수준0.5를 요청0.8로 올리던 처리를 제거했다. 같은 크기 기준의0..1 요청과 기존 작은 onset 강조/attack·release는 유지한다. 입력 수준은 보정된 디지털 특징값이며 실제 음압 dB가 아니다.
- 요청75% 이하: 원래20ms 펄스.75~85%: 비슷한 연속 유음 프레임에서 뒤 펄스 ON 시간을 첫 펄스로 점진 이동.85% 이상: PR80의 긴 펄스. 예:80% 요청의60ms 배치는32ON/4OFF/8ON/4OFF/8ON/4OFF이다. 전체ON48ms와 배치60ms를 보존한다. 실제 무음과 뚜렷한 강약 변화를 건너지 않는다. 정수ms 양자화는 남으며 완벽하게 연속인 체감을 보장하지 않는다.
- AI의 종류별 detail/contrast 증폭을 제거했다. 분류의 이름은 연속성만 확인하며 모든 종류에 동일한 규칙을 적용한다. 신선한 분류 score>=0.65, 선두 차이>=0.08인 동일 문맥에서 작은 흔들림만 EMA(new0.35)로 완화한다. 현재 기본 요청 대비 최대3%p이고75/85% 출력 대역을 바꾸지 않는다. onset>0.2, 변화>0.08, 첫 반응, 실제 무음, 문맥 변경은 기본 요청을 즉시 사용한다. 늦은 첫 문맥은 짧은 이벤트의 첫500ms를 바꾸지 않는다. OFF/만료/실패도 기본 요청으로 즉시 복귀한다.
- 이는 YAMNet 분류 보조의 제한된 시간 안정화다. 신경망 음원 분리·음성 인식·완전한 소음 제거로 표현하지 않는다. 원음은 저장·전송하지 않는다.
- 보정도 같은 인코더를 사용한다. 키는 `output=100|pulse=adaptive75-85-v1`이며 새3초 보정이 필요하다. 기존 숫자 파일을 삭제하지 않고 구형 키로 새 파형을 허용하지 않는다.
